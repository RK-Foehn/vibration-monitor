# 大模型辅助开发与人工验证记录

项目：基于 Zynq 的旋转机械振动状态监测系统  
团队：辽宁大学，郑茜文、白玉轩、王冠杰  
辅助工具：ChatGPT、Codex

## 团队分工与使用方式

本项目由参赛队员确定选题、系统方案和实验安排。团队选用领航者 Zynq XC7Z020 开发板与 LIS3DH 传感器，明确 PL 负责采集和窗口特征计算，PS 负责读取结果及串口传输，电脑端负责显示与记录。寄存器定义、硬件版本和验收顺序由团队确定，开发过程中随硬件进度调整软件任务。

队员承担 PL 设计与硬件调试，完成传感器接线、焊接和固定，操作开发板与电机，采集不同工况的数据并说明实验条件。AI 根据团队提供的 XSA、寄存器头文件和原始报文，参与 ARM 裸机 C 程序、Python 串口工具及辅助脚本的编写与修改，也用于查阅资料、分析报错和整理文档。软件是否适用于本项目，以实际接口、运行记录和团队确认的实验现象为依据。

团队始终负责方案取舍和实验结论。AI 提出的实现建议经过接口检查、编译或软件测试后再用于联调；接线、传感器姿态调整、电机调速及转轴受控扰动均由队员在现场完成。实验数据来自真实采集文件，AI 辅助核算和整理结果。

## 关键协作过程

以下提示词摘自实际会话。除明确标注的原文外，“模型处理”均为过程摘要。

### 1. 按硬件进度安排软件开发

团队提示词原文：

> 目前 AXI Slave 和 PS/PL Block Design 还没实现，所以你暂时先按头文件编写模拟数据处理和 UART 输出程序，不要直接读取不存在的 AXI 外设地址。

模型处理：根据头文件准备模拟数据处理和 UART 输出程序，先建立电脑端串口接收与 CSV 保存流程；收到集成 AXI 外设的新 XSA 后，再准备实际寄存器读取。团队通过这一限制避免软件提前访问尚不存在的外设。

对应材料：`../software/ps_uart_app/`、`../software/pc_monitor/`、`../fpga/docs/axi_register_map_v1.md`。

### 2. 检查硬件平台，修正串口配置

一次早期平台检查中，模型回答原文为：

> 但你发来的 XSA 中 UART0、UART1 都被禁用，所以当前编译出来的是 JTAG 调试输出版本，不能完成要求的串口演示。

该结论针对当时的旧 XSA。团队随后提供启用 UART0 的新文件，并要求：

> 那你就用这次带_uart0的新XSA，把正式串口版程序重新编译好，等板子拿到再测试。

模型处理：核对新 XSA 的 UART 配置，以新硬件平台重新建立串口版应用。团队采用“先看启动输出，再读设备标识，再读窗口特征”的顺序组织实板验证。由此将“程序能够编译”和“板卡能够通过 UART 输出”作为两个分别检查的环节。

对应材料：`../board/results/uart_first.txt`、`../board/results/result_first.json`，以及 `../fpga/vivado/zynq_vibration_system/zynq_vibration_system_uart0.xsa`。

### 3. 按团队接口规范读取窗口结果

团队提示词原文：

> 按照 RESULT_SEQ 读取前后核对的方式获取窗口快照，避免读到不同窗口混合的数据。

团队同时明确了 DEVICE_ID、VERSION、Peak、平方和、样本数、状态和丢帧计数的地址与含义。模型据此编写和检查 AXI 读取、序号一致性判断及 UART 输出代码，随后衔接 Python 报文解析、趋势显示和 CSV 保存。寄存器协议来自团队的硬件设计，软件围绕该协议实现。

对应材料：`../software/ps_uart_app/vibration_uart_app/src/`、`../software/pc_monitor/tests/`、`../data/board/`。

### 4. 由实际工况限定数据解释

团队明确指出：

> 我们目前使用 16 点 X 轴窗口，平方和包含重力直流分量，不能直接把它叫作去重力后的振动 RMS。

队员随后提供正常运行与转轴受控扰动两组 CSV，并说明两组均从低速逐步调到高速。模型按原始文件核算窗口数、Peak 和原始 RMS 的统计量，统一海报、数据说明和界面的指标名称。正常组 105 个窗口、受控扰动组 47 个窗口；两组 Peak 中位数分别为 66 和 606 counts，原始 RMS 中位数分别为 35.59 和 464.67 counts。

本次比较反映所记录工况下的 X 轴计数变化。实验未记录逐档实测转速，也未使用已知故障电机，因此结论限于工况变化与受控扰动响应。

对应材料：`../data/motor_comparison/`。

## 检查、修正与技能提炼

材料整理期间，团队指出初版精简包不能仅凭文件检查就宣称可完整复现。随后补回当前 Vivado 工程的 IP 定义、生成文件、实现资料及构建入口，并分别记录已有实板证据、独立 ARM 编译和上位机测试结果。完整 FPGA 重建尚未执行，该项在构建记录中单列，避免把软件检查结果扩展成整套硬件重建结论。

上述协作形成了 `../skill/` 中的检查流程：先核对 XSA 与 UART 配置，再验证设备标识和窗口读取；区分序号一致性与数据更新、PS 跳过窗口与 PL 丢帧；保留原始报文及实验条件，并逐项对应验证证据。技能包将这些具体问题整理为可复用步骤，供后续相同类型的 Zynq 采集项目参考。
