电脑端振动窗口串口接收工具

现在体验
双击 run_demo.cmd，生成5条模拟窗口数据，保存在本目录 captures 下的新文件夹。
需要电脑已安装 Python（当前电脑已安装）；模拟演示不需要安装其他依赖。
这不是开发板实测，source 字段明确标记 SIMULATED。

接开发板后
在本目录打开终端，依次执行：
python -m pip install -r requirements.txt
python receiver.py --list-ports
python receiver.py --port COM5 --baud 115200
COM5 只是示例，改成实际端口；波特率以 PS BSP 配置为准。
串口设置为8位数据、无校验、1位停止、无流控（8N1）。
先启动接收，再启动/重启板端程序，以捕获元数据和CSV表头。
按 Ctrl+C 停止并保存，也可用 --seconds 60 限时接收。
本工具只读取串口，不向开发板发送命令。关闭其他占用该串口的软件。
打开串口时驱动可能改变控制线状态，板端实际行为需联调确认。
如果无法打开端口或断连，工具打印错误并保留已接收的数据，不自动重连。

生成的文件
windows.csv：可用 Excel 打开（UTF-8 BOM），每行一个校验通过的窗口。
raw_uart.bin：逐字节保存全部原始输入，含乱码和未完成的最后一行。
events.jsonl：启动信息、元数据、警告、错误、拒收原因和计数。
默认每次新建时间戳目录，现有目录不会覆盖；每个数据块刷新到文件。
可用 --out 指定一个尚不存在的输出文件夹。

CSV 字段
received_utc 是电脑接收解析时间（UTC），不是传感器采样时间。
session 在 Hello Zynq 启动标记出现时递增。
source 来自串口元数据；缺失时为 UNKNOWN，不能当作真实数据证明。
seq、peak_raw、sum_squares_raw、sample_count 为窗口数据。
平方和由两个十六进制32位字段组合，保留整数精度；原始量纲是计数平方。
ps_skipped 是板端上报的跳过窗口数。
pc_sequence_delta 是电脑相邻有效记录的无符号序号差；首条为空。
status_live、drops_live 为独立实时诊断值，不属于原子窗口快照。
warnings 标记重复、序号间隔、可能复位/乱序、大间隔及硬件诊断标志。
重复和带诊断标志的数据保留在 CSV 并加警告，不静默删除。
序号间隔不能区分 PL 快照被覆盖、串口漏收、被拒收的数据或未检测到的复位；
完整绕行2^32次也无法仅凭序号判断。drops_live 不等于串口丢包数。

协议范围
仅适配 ps/axi_v1_mock 当前8列 UART格式和原始 X 轴16样本窗口；
不兼容早期 seq,x_mg,y_mg,z_mg 演示。不输出机械振动 RMS 或状态分类。
严格检查列数、数值格式、字段范围、有效标志以及
peak^2 <= sum_squares <= sample_count * peak^2。
乱码、非法行不进入 CSV，原因写入 events，原字节仍完整保留。
单行上限4096字节，超长行丢弃至换行后恢复。
必须收到匹配的表头；中途接入而无表头时请重启板端程序。
未来窗口大小/协议改变，需要同步调整校验；串口协议当前无 CRC，
数值合法并不能排除所有传输位错误。

离线回放
python receiver.py --input "captures\某次接收\raw_uart.bin"
会生成新的独立采集目录，重新校验保存的原始输入。

测试
python -m pip install -r requirements.txt
python -m unittest discover -s tests -v
覆盖分片/超时、乱码、断行、长度上限、复位、回绕、重复和序号间隔、
35位平方和、诊断位、拒绝覆盖目录及 pyserial 软件回环。
软件回环不等于真实 USB-UART、板卡或波特率验证。
