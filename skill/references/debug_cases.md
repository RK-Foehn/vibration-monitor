# 常见故障排查

案例来源及检索词见 [source_ledger.md](source_ledger.md)。以下为历史调试记录，本轮仅整理文档。

## 1. 串口有数据，曲线却一直为直线

记录中的原始行：

```text
12304,181,00000000,0000E11E,16,0,00000015,0
```

历史记录描述它在约两分钟内重复，随后直接 AXI 读取也得到相同窗口。两种读取方式均得到旧窗口，说明需要继续检查结果更新链路。具体停在传感器、SPI、FIFO 或特征计算哪一级，当时没有确认。

排查顺序：

1. 保存带时间的原始报文，检查 SEQ、Peak、SUMSQ、STATUS、DROP。单次重复不等于停机；结合已知窗口周期和 PS 轮询周期判断连续不推进的时长。
2. 若串口在到达而 SEQ 长期不变，暂停基线标定。UI 分别显示“连接状态”和“数据新鲜度”，重复报文记录为事件，不计作新样本。
3. 在授权的调试环境中直接读 AXI 并比对串口。AXI 更新而串口不变：检查 ARM 读取/格式化。串口更新而图不变：检查解析/绘图。AXI 也不更新：沿 PL 结果到采样链排查。
4. 先确认当前 bitstream 是否包含 ILA。若有，观察 xyz_valid、result_valid、FIFO 握手与 SPI；若没有，可在下一版加入样本/窗口计数、状态回读或 ILA，以进一步定位停滞环节。
5. 需要恢复时记录重启前状态，使用匹配的 PS 初始化、bitstream、ELF 受控重启。串口断开重连不复位传感器；PL_RESET 是否覆盖采集链必须查实际 Block Design。
6. 比较重启后电机停转和启动/调速时的 SEQ。重启恢复后仍需查明停滞原因。若现象与电机启动相关，继续检查电源、接地、接触和 SPI，确认是否存在干扰。

STATUS=0x15 或 DROP=0 都不能替代新鲜度检查。没有新采样时 DROP 也可能保持零。

## 2. ILA 看不到多个 100 Hz 样本

记录中的 50 MHz、2048 点捕获仅覆盖 40.96 微秒，远小于约 10 毫秒采样间隔。不要把一次捕获里只有一个样本解释为采样停止。按问题选 xyz_valid 触发、事件采样使能、数据保持或计数器；SPI 边沿问题仍需足够高的观测速率，不能为看长时间而盲目降采样。

先 WHO_AM_I，再完整 XYZ，再 FIFO/窗口，再 AXI，是该项目用于分离故障范围的路径。引脚和复位必须来自当前活动约束，历史接线仅供对照。

## 3. 综合成功，FIFO 却没有用 RAM

历史 OOC 报告中，8×48 bit FIFO 被展开为寄存器，并出现 RAM 推断及 set/reset 警告；记录将其与异步复位过程的写存储模板联系起来。BRAM=0 说明本次没有使用块 RAM；功能和资源是否合适，还要结合警告、测试及规模判断。

复查当前 RTL 模板、真实综合报告和等价行为。小深度寄存器实现可能可接受；扩大深度时再评估标准 RAM 模板或 FIFO IP。若修改复位/存储过程，应回归满空、同时读写、复位与拒收行为。历史 OOC 资源数和时序不适用于后来完整 PS+PL 工程；完整实现必须查自己的时钟约束、WNS/WHS、DRC 和未约束路径。

## 4. Python 依赖与串口连接

缺少 serial 模块时检查当前解释器及 pyserial，使用项目 requirements 和同一虚拟环境运行。收到“接收线程已运行”时先检查程序自己的连接状态；不能直接断言是另一串口助手占用。一次连接只保留一个串口读者。依赖安装、单元测试、模拟回环和真实串口接收是不同证据。

## 5. 电机调速记录

记录后期视频检查描述 SEQ 推进、Peak/原始 RMS 随调速变化，界面仍“未标定”。这可以作为历史展示线索；需取得对应视频/CSV 才能独立复核。没有转速计就不填写数值 RPM；没有正常/异常标注实验就不写识别准确率或故障报警成功。振幅与速度也不必单调，安装结构会影响响应。
