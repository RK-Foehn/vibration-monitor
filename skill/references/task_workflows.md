# 开发与验收流程

根据当前任务选择下列流程，并填入实际路径和文件版本。历史测试数量、交付文件数及 COM 编号只供追溯，验收以本轮记录为准。

## AXI、FIFO 与窗口 RTL

输入：当前 RTL、端口/时钟复位、寄存器规范、C 头文件、测试清单。

在当前授权目标内核对接口，再做最小改动。AXI 覆盖 AW/W 独立到达、读写反压、复位、非法地址和只读保护；窗口只按有效握手提交，检查 seq 一致性与窗口边界。先确认编译文件清单完整，再判断 elaboration 错误是否来自 RTL。运行适用 XSim 用例，保留实际命令、失败日志及通过日志，不改无关采集模块。

输出：改动清单、场景覆盖和实际 PASS/FAIL；E1 不能替代 E3。测试数量随实际场景确定。

## PS/PL 平台与应用移交

从当前 BD、活动 XDC、XSA 核对 M_AXI_GP0、FCLK、复位极性/释放、AXI 地址、SPI 四线、UART MIO 与 DDR。检查 XSA 内 UART enable 和 bitstream，并对比实现 bitstream 哈希。用新工作区生成平台/BSP，使用匹配初始化与 ELF。先 DEVICE_ID/VERSION，再 SEQ 和真实窗口，最后 UART/Python。只列本次实际达到的阶段。

XSA 含 bitstream 不等于包含应用 ELF，也不能单凭 XSA 证明全部 RTL 与该二进制字节级对应；需要来源版本、构建日志和哈希记录。

## UART 与 PC 接入

先读取真实 C 发送代码、现有解析器和原始报文。按真实列数、进制及行分类解析，复用现用 CSV 逻辑。覆盖启动文字、重复表头、诊断行、破损行、n=0、重复 seq 和 seq 跳变。保留原始数据与解析错误事件，错误行不进入特征曲线。接收非阻塞，连接状态和数据新鲜度分开。先离线/回环，再在实际串口确认数据来源；Demo 数据醒目标注。

源码核对记录：helloworld.c 使用约 500 ms 间隔，成功输出计数每 20 条重发来源/表头，并可打印 snapshot_rc 诊断。十六进制字段为第 3、4、7 列，其它数据列十进制。重发周期属于当前实现，解析器不应依赖它精确不变。COM 选择来自实际枚举，不固定 COM8。

## 架构扩展与时序分析

算法划分先给输入输出、位宽/符号、状态依赖、吞吐、延迟、PS/PL 边界、CDC、带宽和验收。资源无法估算则标待综合，优先保持当前可演示链路。时序分析只用同一构建的约束、utilization、timing summary 和关键路径；检查未约束路径、WNS/TNS、保持时序、逻辑/布线延迟和 ILA 开销。给出少量有证据的问题与最小修复；时序满足要求时，记录通过情况。

任何流水线/资源共享改动均回归接口及功能，同条件比较实现前后结果。历史 OOC 报告不能充当本次完整系统结果。

## 固定工况实验与报告

使用安装方向不变、可靠固定、带工况标签的真实 CSV；先排除过期/破损窗口并记录 skipped/drop。按工况分析 Peak/raw RMS 分布及重复性，阈值仅在训练/标定数据选取，再用独立记录检验误报。没有真实故障样本就仅称相对基线偏离，不报故障识别率。电机和传感器保持安全固定，不采用触轴、松支架或易甩脱配重造异常。

报告按当前正式模板检查字数、图片、匿名要求；补充材料提及的旧章节结构不是永久规则。真实照片、日志、CSV 与软件版本对应，证据不足标待补。无测速设备不填写数值 RPM。
